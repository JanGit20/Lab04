Wprowadzenie do Gita

Git to rozproszony system kontroli wersji pozwalający na śledzenie historii zmian w kodzie oraz efektywną współpracę zespołową.

Standardowa procedura pracy

  1. Synchronizacja: pobranie najnowszego stanu gałęzi głównej (git pull).
  2. Branch: utworzenie i przejście na nową gałąź zadaniową (git switch -c nazwa-brancha).
  3. Zmiana: edycja plików, implementacja funkcjonalności lub poprawki w kodzie.
  4. Commit: przygotowanie zmian i zapisanie lokalnego punktu kontrolnego (git add, git commit).
  5. Push: wysłanie gałęzi ze zmianami do zdalnego repozytorium (git push).
  6. PR: utworzenie Pull Requesta na GitHubie i poddanie kodu procesowi code review.

Tabela poleceń Git

Zestawienie najważniejszych poleceń
Polecenie Opis działania
git clone <url> Klonuje istniejące zdalne repozytorium na lokalny komputer.
git status Wyświetla stan drzewa roboczego i przygotowanych plików.
git add <plik> Dodaje zmiany z obszaru roboczego do indeksu (staging area).
git commit -m "opis" Tworzy nowe zatwierdzenie ze zmian znajdujących się w indeksie.
git push Wysyła lokalne zatwierdzenia na zdalny serwer (np. GitHub).
git pull Pobiera i scala zmiany ze zdalnego repozytorium do bieżącej gałęzi.
git fetch Pobiera metadane i historię ze zdalnego repozytorium bez scalania kodu.
git branch Wyświetla listę gałęzi lokalnych lub tworzy nową gałąź.
git switch <nazwa> Przełącza bieżący kontekst pracy na wskazaną gałąź.
git log Prezentuje historię zatwierdzeń (commitów) w bieżącej gałęzi.
